# TNG50 snapshot-99 galaxy-region cutout exporter

This repository exports galaxy-centered regions for all 8,252 TNG50-1 galaxies
listed in `Environment_maj` at snapshot 99. The default target manifest,
[`targets_snap99.csv`](targets_snap99.csv), was generated by joining the
snapshot-99 `Environment_maj` rows to `SubhaloGrNr` for the parent FoF halo ID;
the targets span 4,698 unique parent FoF halos. It is intended to run inside the
[IllustrisTNG JupyterLab](https://www.tng-project.org/data/lab/), where the full
snapshot data and `illustris_python` are already available.

By default, each output is an axis-aligned cube **300 physical kpc across**,
centered on that target galaxy's `SubhaloPos`. Particle coordinates remain in
their original TNG units (`comoving kpc/h`), and periodic box boundaries are
handled when selecting the region. Particles are drawn from the target's parent
FoF halo, so the local circumgalactic environment is retained without writing
the entire halo.

The exporter writes the fields requested from the web cutout API, plus
velocities:

- Gas (`PartType0`): `Coordinates`, `Velocities`, `Masses`, `GFM_Metallicity`,
  `Density`, `ElectronAbundance`, `InternalEnergy`, and `StarFormationRate`.
- Stars/wind (`PartType4`): `Coordinates`, `Velocities`,
  `GFM_StellarFormationTime`, `GFM_InitialMass`, and `GFM_Metallicity`.

`Velocities` keep the raw snapshot units, km sqrt(a)/s. Multiply by sqrt(a)
to get peculiar velocities in km/s. Cutouts finished by an older version
without `Velocities` are upgraded in place on the next run: only the missing
fields are streamed and appended.

## Run in the TNG Lab

Open a terminal in the Lab and clone this repository:

```bash
git clone https://github.com/astroferreira/tng50-halo-cutout-exporter.git
cd tng50-halo-cutout-exporter
python export_missing_halos.py
```

Or run it from a notebook cell:

```python
%cd ~/tng50-halo-cutout-exporter
%run export_missing_halos.py
```

The default working-array memory budget is 256 MiB. For a smaller Jupyter
kernel, start with 128 MiB:

```python
%run export_missing_halos.py --memory-budget-mib 128
```

Generated files go into `snap99_galaxy_cutouts_300kpc/`. These spatially cropped
files should be smaller than full-halo exports, although the exact total depends
on the particle density around each galaxy. Check your writable-storage quota
before starting a full snapshot-99 run.

## Useful commands

Preview all targets without touching the simulation data:

```bash
python export_missing_halos.py --list-targets
```

Test one target first:

```bash
python export_missing_halos.py --only 99 637468
```

The two values passed to `--only` are `SNAPSHOT SUBHALO`, not the parent-halo ID.

Choose another physical cube width if needed:

```bash
python export_missing_halos.py --size-kpc 300
```

Put disk-backed scratch files on a specific writable filesystem and retain a
free-space reserve:

```bash
python export_missing_halos.py \
  --memory-budget-mib 128 \
  --work-dir ~/tng-cutout-work \
  --min-free-gib 5
```

Do not put `--work-dir` on `/dev/shm` or another RAM-backed filesystem. By
default it is `OUTPUT_DIR/.work`, which is the safest choice in the Lab.

Use an explicit simulation mount or destination:

```bash
python export_missing_halos.py \
  --base-path ~/sims.TNG/TNG50-1/output \
  --output-dir /path/with/enough/space/snap99_galaxy_cutouts_300kpc
```

Run the original 80 missing-target job, preserved as
[`targets_missing.csv`](targets_missing.csv), by passing it explicitly:

```bash
python export_missing_halos.py \
  --targets targets_missing.csv \
  --output-dir missing_galaxy_cutouts_300kpc
```

Export the PMCTRL merger/control sample, preserved as
[`targets_pmctrl100_snap50_99.csv`](targets_pmctrl100_snap50_99.csv). It lists
the SubLink main-branch nodes of 50 post-mergers and 50 matched controls at
every snapshot from 50 (z = 1) to 99: 4,997 galaxies in 4,703 parent halos.

```bash
python export_missing_halos.py \
  --targets targets_pmctrl100_snap50_99.csv \
  --output-dir pmctrl100_galaxy_cutouts_300kpc
```

Run it in a terminal multiplexer if available:

```bash
tmux new -s tng-export
python export_missing_halos.py 2>&1 | tee export.log
```

Detach with `Ctrl-b`, then `d`, and later reconnect with
`tmux attach -t tng-export`.

## Resuming and downloading

The job is safe to restart:

- Finished `.hdf5` files are skipped.
- In-progress files use the `.hdf5.part` suffix.
- Each dataset is first written under a temporary name, so an interrupted field
  is rewritten on the next run.
- `generation_status.json` records completed and failed targets.

## Memory safety

The exporter does not call `snapshot.loadHalo()` for particle data. That helper
allocates a complete halo field before returning it, which can exceed the
Jupyter kernel's memory limit for halos 0–3. Instead, this exporter:

- obtains only the halo offsets and lengths from `illustris_python`;
- reads the underlying snapshot pieces in bounded hyperslabs;
- stores the full selection mask and reusable field buffers as NumPy memmaps;
- derives chunk sizes from `--memory-budget-mib`;
- keeps the HDF5 read cache at 1 MiB and explicitly releases each scratch
  buffer;
- checks output and scratch free space while retaining `--min-free-gib`; and
- reports peak process RSS after each particle type.

Scratch memmaps are removed after each particle type. If the kernel is killed,
rerunning the same command safely truncates/reuses any stale scratch file and
resumes the `.hdf5.part` output at the field level.

To make a single downloadable archive after the run:

```bash
tar -C snap99_galaxy_cutouts_300kpc -czf tng50-snap99-galaxy-cutouts.tar.gz \
  --exclude='*.part' --exclude='generation_status.json*' .
```

For large outputs, downloading individual completed `.hdf5` files or using
`rsync`/`scp` is generally more reliable than creating one huge browser download.

## Notes

- The default source target list is [`targets_snap99.csv`](targets_snap99.csv).
- The original 80 missing-target list is preserved as
  [`targets_missing.csv`](targets_missing.csv).
- Output names have the form
  `cutout_TNG50-1_<snapshot>_<subhalo>_<parent-halo>.hdf5`, matching the existing
  compatibility filenames used by the SKIRT campaign.
- Snapshot `Header`, `Parameters`, and `Configuration` attributes are copied into
  each output, and particle counts are updated for the cutout.
- Each output records its subhalo, parent halo, center, physical size, geometry,
  and coordinate units as HDF5 root attributes.
- The exporter streams one bounded chunk at a time and writes only selected
  particles; it never materializes a complete parent-halo field in RAM.
- No TNG API key is needed because this reads the Lab's mounted snapshot data.

See the official TNG documentation for
[`illustris_python` data access](https://www.tng-project.org/data/docs/scripts/)
and the TNG forum guidance on using
[`snapshot.loadHalo()` for Lab cutouts](https://www.tng-project.org/data/forum/topic/887/cutouts/).
